# Roadmap

This document states direction, not dates. Exact current support is defined by source and validation evidence.

## Current foundation

- publish the beta repository and current application catalogue
- verify package metadata, retention and signing logic through tests
- exercise representative install/upgrade/remove behaviour in Linux Mint userspace

## Near-term priorities

- strengthen signing readiness and repository self-verification
- keep package discovery resilient without weakening immutable release identity
- standardise software-centre presentation through shared Common web primitives

## Longer-term direction

- broaden lifecycle qualification as the application family grows
- support additional repository channels only when their promotion/retention semantics remain explicit

## Admission rule

New work needs clear ownership and a realistic validation path. A feature is not "supported" merely because an external service, generic protocol or neighbouring product can perform something similar.

## Completion rule

Implementation, tests, user-visible behaviour and maintained documentation must agree before an item is complete.
